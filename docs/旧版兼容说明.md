# 旧版 CFTE 配置与解算规则

修改前代码基线：0afd8e5（保存兼容性补齐前的PCM处理代码基线）。

本次以 PCMProcess-20260226/PCMProcess-20241224/PCMProcess 中的
DaitouOutputDialog.cpp、PCMProcessDlg.cpp、INETCHULIThread.cpp 为依据。
配置导出和传统处理统一使用旧版 CFTE 规则，不再保留此前按用户采样率合成时间轴的处理路径。

## 配置格式

- 签名为 #CFTE/filemain/rec01.00。
- 流格式段为 The format description of stream N:。
- 参数段为 the_parameter_description_of_stream N:，stream 与编号之间为空格。
- 参数描述字段使用 Description:。
- 导入接受此前下划线参数段名和小写 description，导出统一为旧版格式。
- UTF-8 优先；旧 Windows 文本按 GB18030 解码。Qt 6 构建增加 Core5Compat 依赖。
- coefficient 保存逗号分隔系数；segment_number 与重复的 code,phy 保存点表；
  segment_point、first_segment、second_segment 保存双曲线数据。
- 配置管理中的新增、编辑和导出均保留校准字段；编辑器内多个 code,phy 点用分号分隔，
  导出时恢复为逐行重复的 code,phy:。
- 未提供系数、点数不符、重复码值、非法或非有限校准数值会报错，避免静默输出未校准值。

## 时间与采样

- 原始 PCM 使用 16 位小端存储字；配置的有效字长允许 1..16 位。
- 时间来自 HOUR_N、MINUTE_N、SECOND_N，可选 MSSECOND_N。
  也接受无流号后缀的同名时间参数。至少前三项必须存在。
- 根据 Onboard_acq._equipments_type 解码 DM6、秦川、KAM500、770、JQD、
  UMA2000、XFC100、XMA、XYD、TTC 时间字；未知设备名按旧版普通时间字规则处理。
- major_frame_rate 是长周数/秒；参数 rate 是每个长周中的出现次数。
- 用户处理采样率为正整数。小于等于长周率时，每 floor(长周率/处理采样率) 个长周抽取一个。
- 高于长周率时，沿用旧版整数商和四舍五入步长：
  step = max(1, round(最大出现次数 / floor(处理采样率/长周率)))。
  处理采样率不保证对任意整数请求都能精确达到，也不会人为改变时间码。
- 低频参数沿用旧版地址矩阵补点；高频参数按子帧内重复位置读取。
  最大出现次数无法整除所选参数出现次数等不明确布局会明确拒绝。
- 每个时间段先定位到时间码不小于起点的完整长周，再重新计算抽取相位。
  长周内第 k 个输出位置的时间为 长周时间码 + k/(长周率×最大出现次数)。
- 输出窗口采用 [开始, 结束)，所有范围独立输出。
- 多子帧长周检查同步字与从 0 开始的子帧 ID 顺序；前导噪声和丢同步在有界窗口内重同步。
  末尾不完整长周记录告警并丢弃。

## 位拼接与校准

- frame_no、word_no 为 0 基索引，source_bit 从最低有效位起算。
- 所有有效 object_bit 为 0 时，按段顺序从高位到低位拼接；
  否则先将各段左移对应 object_bit，再按位或合并。
- 目标位超出 64 位会报错。重叠目标位按旧版 OR 规则处理。
- inverse 表示读取 PCM 字后交换两个字节，不是按位取反。
- line 和 poly 按旧版多项式系数顺序计算：a0+a1*x+a2*x²+...。
- segm 在点间线性插值，在两端沿最近线段外推。
- hyper 根据阈值选择一组四项系数，计算 a/(b+c*x)+d；分母为零报错。
- 支持旧版 sint、xint、fcs618、fcsf；16 位飞控数值按有符号整数解释，
  32 位按浮点位模式解释。fillcode 使用有符号值与分段校准。

## 执行与验证范围

旧版处理在工作线程中运行。各流使用分块读缓冲和单长周结果缓冲，
按实际时间码归并并流式写出，避免把整个任务的结果保存在内存中。
取消或失败不提交当前结果，已完成时间段的文件保留。
时间码倒退会明确报错；本次未增加跨日时间码自动展开。

使用本机 Qt 5.14.2 / MinGW 7.3.0 Release 构建，12 个 CTest 目标全部通过。
新增测试用手工构造的旧版 CFTE 和 PCM 字值，验证时间码、采样相位、
12 位有效字长的 16 位存储、目标位拼接、字节交换、校准、参数保留、
多流、多时间段、取消、重同步和输出提交。

外部源码目录未找到可用于逐行对照的真实 .hea / PCM 数据。
因此本次验证是基于旧源码算法和构造数据的回归，不是实际飞行数据的双程序结果比对，
也没有进行百 GB 规模性能测试。此实现面向上述 CFTE 配置，未扩展独立的“小系统”非 CFTE 头文件语法。
