# 20 GiB 数据性能对比与优化

在用户确认的同一参数组、1 Hz、关闭原码输出条件下，优化前实测
169.3 秒；优化后连续两次为
30.0 秒和 31.5 秒，
提速 5.4～5.6 倍。
两次完整输出均与优化前逐字节一致。

## 对比条件

| 项目 | 条件 |
| --- | --- |
| 原始数据 | generated/all_methods_1000_20g/raw.pcm，21,474,836,480 字节（20 GiB） |
| 配置 | 同目录 config.hea，1004 个参数 |
| 参数组 | generated/performance/parameters.txt，从本机 GUI 已保存设置读取；TIME 加 1004 个参数 |
| 采样与输出 | 1 Hz，只输出工程值，完整时间范围 |
| 构建 | Windows，Qt 5.14.2，MinGW 7.3，Release |
| 处理入口 | pcm_dataset_decode，与 GUI 共用 TraditionalProcessingController 和 FastFixedPcmProcessor |
| 输出规模 | 81,920 行数据，1,005 列，500,687,714 字节 |

| 版本 | 耗时 | 数据来源 |
| --- | ---: | --- |
| 旧版软件 | 25 秒 | 用户提供，本次没有重新自动计时旧版 GUI |
| 优化前新版 | 169.3 秒 | 本机完整文件实测 |
| 优化后新版，第 1 次 | 30.0 秒 | 本机完整文件实测 |
| 优化后新版，第 2 次 | 31.5 秒 | 本机完整文件实测 |

计时包含配置加载、解算和输出提交，不包含事后计算输出 SHA-256。
最终测试串行执行，计时期间没有并行运行项目编译或另一项解算基准。
结果未达到用户报告的旧版 25 秒，差距已缩小到约 5～7 秒。
这不代表已经证明旧版与新版的全部输出数值一致；本次完整比对针对优化前后新版。

## 慢的原因及改动

1. **固定布局工作重复执行。** 之前每个长周调用完整参数校验、筛选和出现次数计算，
   包括 1 Hz 降采样时最终会丢弃的长周。新增每流独占的 LegacyPcmDecodePlan，
   在启动时校验并预计算时间字位置、拼字掩码、出现地址步长和采样步长。
   实际时间码、时间倒退、帧同步和数据长度仍逐帧检查。
2. **每个采样值重复构造拼字布局并转换原码。** 预计算计划直接读取已校验的位置，
   复用同一长周内的低频补点值；关闭原码输出时省去第二次原码转换。
   已排序的分段校准表直接借用，外部传入无序点时仍兼容排序。
3. **同一输出行反复格式化时间和查找列。** 时间仅在时间戳改变时格式化，
   仍以原有高精度分行键区分同一可见毫秒内的多个采样点。
   已验证身份的固定列顺序直接定位；乱序、缺列或跨流时回退到按流和 ID 查找。
   数字保留原来的 17 位有效数字和 64 位整数精度，每行集中写入 QTextStream。
4. **原始数据复制及单流结果归并开销。** 长周使用只在同步解算期间有效的字节视图；
   单流有序结果直接整块交给 ResultWriter，减少逐值归并和二次复制。
5. **读取与处理串行等待。** 使用 QtConcurrent 每流预读下一块，与当前块的解算、写出重叠。
   QFile 在预读线程内创建和关闭，通过 QFuture 交接数据。
   每流最多一个在途预读，双缓冲轮换复用容量；本例每块 32 MiB。
   块尾不足长周时拼接到下一块；停止、失败或结束时等待已有预读回收。

最终两轮工作线程日志显示，读取等待约 25～46 ms，参数解算约 5.6～6.2 秒，
结果写入约 19.0～19.6 秒。读取等待不等于磁盘读取总耗时，预读与计算已经重叠。
工作线程之外的配置加载等约 2 秒；剩余热点主要是大量数字的文本转换。

## 验证与复现

完整输出 SHA-256：

`8d0337d5d84745e446c353ba2663da45e8a2b6df4b67ab2bf3c127d5d32741fd`

首、中、尾各 64 个真实长周另以 128 Hz、同时输出原码和工程值解算，
对照独立生成的 expected.txt；合计 3,072 行、6,147,072 个单元格通过。
新增回归覆盖 1/2/8/16/64/128 Hz、原码开关、长周内补点、
64 位和重叠目标位拼字、字节交换、无序校准点、短帧、异常时间、
跨流同 ID、乱序列、批次切割、4 KiB 预读边界、同步恢复和取消。

计时及逐项结果见 `generated/performance/verification.json`。
可在项目根目录设置 Qt/MinGW 运行库 PATH 后执行：

```powershell
python generated/performance/run_final_verification.py
```

命令行入口新增 `--engineering-only` 与 `--timeout-seconds`，例如：

```powershell
./build-performance/pcm_dataset_decode.exe --config generated/all_methods_1000_20g/config.hea --raw generated/all_methods_1000_20g/raw.pcm --parameters generated/performance/parameters.txt --sample-rate 1 --engineering-only --timeout-seconds 600 --output generated/performance/manual.txt
```

12 组 CTest 全部通过；交付目录另在去除 Qt/MinGW 安装路径的环境中，
通过 Windows 平台 GUI 测试和 128 Hz 样本验证。

附加检查中，offscreen 平台运行 GUI 弹窗测试时在 Qt5 QMessageBox 调用栈崩溃；Windows 原生平台的同一套测试通过。交付验证以 Windows 原生平台为准，Linux/macOS 未实测。

## 使用优化版

启动 `build-performance/pcm_process_gui.exe`。该目录单独构建并配齐 Qt/MinGW 运行库。
已经运行的 `build-legacy-verify/pcm_process_gui.exe` 实例使用其启动时的代码；
需要启动上述优化版程序才能复测本次改动。
