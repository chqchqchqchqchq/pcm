# 全参数解算数据生成与验证

使用 tools/generate_all_methods_dataset.py 生成符合旧版 CFTE 规则的合成数据。
默认输出 generated/all_methods；生成文件不加入 Git，生成器与验证入口保存在源码中。
此前 generate_test1000_dataset.ps1 只有无校准 uint 示例，完整兼容性验证请使用本生成器。

## 在 GUI 中加载

| 项目 | 文件或设置 |
|---|---|
| 配置 | generated/all_methods/main/config.hea |
| 原始数据 | generated/all_methods/main/raw.pcm |
| 参数组 | generated/all_methods/main/parameters.txt |
| 时间段 | 全程 |
| 处理采样率 | 32 |
| 原码输出 | 勾选 |
| 对应预期 | generated/all_methods/expected/main_rate32.txt |

主配置为 GB18030 编码；同目录 config_utf8.hea 是同内容 UTF-8 文件。
配置使用 the_parameter_description_of_stream 1: 和 Description: 等旧版段名、字段名。
默认有 4 个时间参数、40 个业务参数、1024 个长周，PCM 文件为 2 MiB。
时间从 01:02:03.000 开始，每秒 4 个长周，总时长 256 秒。
每个子帧 256 字、长周包含 4 个子帧；每字按 16 位小端存储。

## 覆盖内容

- uint、sint、bcd、xint、fcs618、fcsf，以及 float 原码别名。
- NO、line、poly、segm、hyper，以及 float、double、fillcode 特殊处理。
- 8/12/16/32/64 位边界、负值、超过双精度精确整数范围的 64 位值。
- 六项多项式、分段插值与两端外推、双曲线阈值两侧及阈值本身。
- LSB 源位、逐字节交换、连续拼字、目标位留空/重排/重叠 OR、跨子帧和六段拼接。
- 每长周 1/2/4/8 次采样、低频参数补点、子帧内重复采样、抽取和时间窗口。
- DM6、秦川、KAM500、770、JQD、UMA2000、XFC100、XMA、XYD、TTC 时间码。
- 12 位有效数据使用 16 位物理存储、UTF-8 与 GB18030 配置导入。

详细参数布局、刺激值、校准系数、文件 SHA-256 和 21 项用例定义见 manifest.json。
expected 目录由独立刺激值模型计算期望，actual 目录由生产控制器写出真实结果。
验证逐行逐列比较时间、原码和工程值，整数精确比较，浮点允许格式舍入误差。
verification.json 保存验证结果和验证时的解算器、清单 SHA-256。
数据是合成回归夹具，尚未与真实采集文件或旧版可执行程序输出逐行对照。

## 重新生成

在仓库根目录执行：

    python tools/generate_all_methods_dataset.py --frames 1024

构建共用 GUI 生产控制器的命令行入口：

    cmake -S . -B build-legacy-verify
    cmake --build build-legacy-verify --target pcm_dataset_decode --parallel 6

验证已有生成文件：

    python tools/generate_all_methods_dataset.py --verify-only --decoder build-legacy-verify/pcm_dataset_decode.exe

也可同时传 --decoder 在生成完成后立即验证，或用 --output 指定输出目录。
Windows 运行解算器前，需要将当前构建所用 Qt 和编译器的 bin 目录加入 PATH。
每次重新生成都会将旧验证报告标记为尚未校验，避免误用上一次的通过结果。

## 1000 参数、20 GiB 数据集

使用 tools/generate_large_all_methods_dataset.py 生成：
generated/all_methods_1000_20g/config.hea、raw.pcm 和 parameters.txt。
配置共 1000 个业务参数和 4 个时间参数，PCM 大小为 21,474,836,480 字节。

每子帧 2048 字、每长周 8 个子帧，满足旧版 frame[2048] 的缓冲上限。
长周率为 8 Hz，参数 rate 为每长周 1/2/4/8/16 次，实际采样率为 8/16/32/64/128 Hz。
完整频次解算时处理采样率填 128 Hz，所有采样相关频率均为 2 的幂。
长周间隔 125 毫秒，DM6 时间码可精确表示；20 GiB 全程保持在同一天内。

生成并验证：

    python tools/generate_large_all_methods_dataset.py --decoder build-legacy-verify/pcm_dataset_decode.exe

程序全文件重新读取核对 SHA-256，并从首部、中部、尾部各取 64 个长周，
使用生产控制器比对全部 1000 个业务参数的原码和工程值。
报告见数据目录下的 verification.json，详细加载说明见 README.md。

actual 输出旧版 TIME 列和 HH:mm:ss:zzz 格式，expected 保留精确秒数作为独立预期。

配置按本文件最长普通字段名确定对齐宽度，字段名前只补必需的空格，冒号对齐；bits_order 保留旧版语法要求的一个冒号前空格；The format description of stream N: 和 the_parameter_description_of_stream N: 段标题顶格书写，不参与对齐。


## 旧版打开路径验证

旧版打开数据和解算线程的 frame 缓冲均只有 2048 个 16 位字。原 4096 字子帧已替换，
长周大小仍为 32768 字节，因此 20 GiB 文件的时间范围保持 01:02:03.000 至 23:47:23.000（右开）。
生成器按物理占用重新分配参数地址，高频布局优先放置，保留 1000 个业务参数与 4 个时间参数。
新增 RATE16 补足 8 子帧条件下的子帧内重复采样验证。

创建日期沿用旧版的 Create_date:日期 时间 写法；bits_order 按旧版 fscanf 格式写为
bits_order : normal，冒号仍与其他字段对齐，只有一个必要的语法空格。

构建并验证旧版打开路径：

    cmake --build build-legacy-verify --target pcm_legacy_open_probe
    python tools/verify_legacy_dataset.py --directory generated/all_methods_1000_20g --probe build-legacy-verify/pcm_legacy_open_probe.exe

报告 legacy_open_verification.json 检查旧版头部 fscanf 的全部转换、固定缓冲上限，
并调用原始 read_subf 读取首尾长周。此检查并非旧版 GUI 的全参数结果比对。

参数名统一为 参数名_流号，例如 UINT8_1、UINT8_G02_1；HOUR_1 等已有正确后缀的名称不重复追加。
